# Remaining Development Backlog

현재 백엔드는 기획서/기능 명세서 기준 API 표면을 먼저 맞춘 MVP입니다. 남은 작업은 아래처럼 제품 완성도와 실제 서비스 전환에 필요한 영역으로 나눌 수 있습니다.

## 1. P0 - 실제 서비스 기반 전환

| 항목 | 현재 상태 | 개발할 내용 |
| --- | --- | --- |
| 데이터 영속화 | JPA Entity/Repository 적용 | 운영 DB 마이그레이션과 인덱스 보강 |
| DB 스키마 | 사용자, 계좌, 카드, 거래, 예정 이벤트, 반복 규칙, 예산, AI 대화 테이블 초안 구현 | ERD 확정, 제약 조건/인덱스 정교화 |
| 마이그레이션 | Flyway V1 도입, Hibernate validate 적용 | 운영 변경분별 마이그레이션 추가 |
| 인증/인가 | Bearer dev token, `X-User-Id` 개발용 사용자 컨텍스트, 주요 리소스 소유권 검증 | OAuth2/JWT 운영 인증 도입 |
| 입력 검증 | 기본 validation | 날짜 범위, 금액, 반복 규칙, 중복 이벤트, 예산 한도 검증 강화 |
| 오류 코드 | 공통 포맷만 구현 | 명세서 기준 비즈니스 오류 코드 체계화 |

## 3. P1 - AI Agent / Fine-Tuning 관련

기획서의 "파인 튜닝"은 바로 모델 fine-tuning 파일을 학습시키는 것보다, 먼저 사용자 금융 데이터를 잘 읽고 일관되게 답하는 개인화 튜닝 레이어로 접근하는 것이 안전합니다.

| 단계 | 개발할 내용 | 산출물 |
| --- | --- | --- |
| 1단계: 프롬프트 튜닝 | 날씨 상태, 사용 가능 자금, 예정 지출 근거를 항상 포함하는 시스템 프롬프트 설계 | Prompt template, 답변 포맷 |
| 2단계: Tool Calling | dashboard, financial-events, forecasts 도구 스냅샷 기반 답변 구조와 OpenAI 호환 어댑터 적용 | 실제 운영 키/프롬프트/eval 연결 |
| 3단계: RAG | 상품/카드 추천, 절약 팁, 금융 지식 문서 검색 | Vector DB, document chunking |
| 4단계: 사용자별 개인화 | 사용자의 반복 지출, 소비 카테고리, 위험 허용 기준 반영 | User preference profile |
| 5단계: 평가 데이터셋 | 대표 질문/정답/근거 모음 작성 | Eval set, regression test |
| 6단계: Fine-tuning 검토 | 반복적으로 실패하는 말투/분류/추천 패턴이 쌓이면 별도 fine-tuning 검토 | Fine-tuning dataset |
