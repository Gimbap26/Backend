# 06. 개발 가이드

## 실행

| 방법 | 명령 | 비고 |
| --- | --- | --- |
| 테스트 | `mvn clean test` | **`clean` 을 붙일 것** (아래 함정 1) |
| 빌드 | `mvn clean package` | `target/money-weather-api-0.0.1-SNAPSHOT.jar` |
| 실행 | `java -jar target/money-weather-api-0.0.1-SNAPSHOT.jar` | H2 메모리 DB, 데모 데이터 자동 생성 |
| 다른 포트 | `... --server.port=8081` | |
| PostgreSQL | `docker compose up -d` 후 `... --spring.profiles.active=postgres` (`JWT_SECRET` 필요) | |
| 배포 | `docker compose -f docker-compose.prod.yml up -d --build` | 루트 README 의 "홈서버 배포" |

- `mvn` 이 PATH 에 없으면 IntelliJ 번들 Maven: `C:\Program Files\JetBrains\IntelliJ IDEA <버전>\plugins\maven\lib\maven3\bin\mvn.cmd`
- IntelliJ 실행 설정(`MoneyWeatherApiApplication`)의 Environment variables 에 `AI_API_KEY` 를 넣으면 외부 AI 를 씁니다. `.idea/` 는 git 제외라 키가 저장소에 올라가지 않습니다.
- 기동 로그에서 확인할 것: `Successfully applied N migrations`, `AI 답변기: ...`, `Started MoneyWeatherApiApplication`

## 자주 걸리는 함정

1. **지운 클래스가 계속 실행된다** — `mvn test` 는 소스를 지워도 `target/` 의 `.class` 를 지우지 않습니다. 실제로 삭제한 `UserContextFilter` 가 계속 로드된 적이 있습니다. 파일을 지우거나 옮긴 뒤에는 **`mvn clean`**.
2. **프로젝트 경로에 한글이 있으면 `mvn spring-boot:run` 이 실패** (`ClassNotFoundException`). jar 로 실행하세요.
3. **8080 포트가 이미 사용 중** — 이 PC 에서는 National Instruments 의 `NI Application Web Server`(자동 시작 서비스)가 8080 을 씁니다. `--server.port=8081` 로 띄우거나 관리자 권한으로 `Stop-Service NIApplicationWebServer`.
4. **Git Bash 의 `curl -d` 로 한글을 보내면 400** — 터미널이 CP949 로 보냅니다. API 문제가 아닙니다. Swagger 나 파일로 보내세요(`--data-binary @body.json`).
5. **`/dev/seed` 후 401** — 초기화하면 사용자가 새로 만들어져 기존 토큰이 무효입니다. 다시 로그인.
6. **데모 계정으로 로그인이 안 됨(429)** — 틀린 비밀번호로 5번 시도하면 15분 잠깁니다. 기록은 메모리에만 있으니 서버를 재시작하면 풀립니다.
7. **조회 API 에 `readOnly` 를 붙이면 안 되는 곳** — 대시보드·예측·예정 이벤트·시뮬레이션은 조회 전에 이벤트를 만듭니다([04 D1](04-의사결정-기록.md#d1-반복-규칙-이벤트는-조회할-때-만든다)).
8. **다른 서비스의 404 를 try/catch 로 넘기면 500** — 트랜잭션이 롤백 전용이 됩니다. 먼저 존재를 확인하세요(`BudgetService.exists()` 패턴, [02](02-구조와-핵심-개념.md#트랜잭션에서-주의할-점)).

## 코드를 추가할 때

| 하려는 것 | 따를 방식 |
| --- | --- |
| 현재 사용자 | `CurrentUserService.require()` / `requireId()`. 요청 파라미터로 사용자 ID 를 받지 말 것 |
| 다른 사용자 리소스 차단 | 조회 후 `currentUser.assertOwner(entity.getUserId(), userId)` |
| 오류 응답 | 서비스 패키지의 `Errors.notFound/badRequest/conflict(...)`. 형식은 `ApiExceptionHandler` 가 통일 |
| 잔액을 바꾸는 기능 | 반드시 `LedgerService` 를 거칠 것 (되돌리기 → 변경 → 적용) |
| 예정 이벤트를 읽는 기능 | 읽기 전에 `ScheduleService.materializeRange(userId, from, to)` |
| 요청·응답 DTO | 컨트롤러의 요청 `record` 에 검증 어노테이션(`@NotNull` 등), 응답 DTO 는 소유 서비스 안의 `record` |
| DB 변경 | 새 `V6__...sql` + 엔티티 필드. 기존 마이그레이션 수정 금지 |
| AI 도구 추가 | `AgentTools` 생성자에서 `register(이름, 설명, JSON 스키마, 실행)`. 설명은 모델이 읽고 도구를 고르는 기준이므로 구체적으로. 규칙 기반 답변기도 필요하면 `RuleBasedAgentAnswerClient.classify` 에 의도 추가 |
| 공개 API 추가 | `SecurityConfig.PUBLIC_PATHS`. 그 외는 자동으로 인증 필요 |
| 설정값 | `application.yml` 에 `${ENV_VAR:기본값}`. 운영에서 반드시 필요한 값은 `application-postgres.yml` 에 기본값 없이 |

주석은 한국어로 "왜"를 적는 스타일입니다. 코드가 무엇을 하는지는 코드로 보이게 하고, 이유나 함정이 있을 때 주석을 남깁니다.
