## 시작 시점의 문제

엔드포인트는 31개가 모두 있었지만, 코드를 읽어 보면 몇 개는 **이름과 다르게 동작**했습니다.

| 문제 | 내용 |
| --- | --- |
| 반복 규칙이 반복하지 않음 | 시작 월에 이벤트 1건만 만들고 끝. `WEEKLY`/`YEARLY`는 조용히 무시, `endDate`는 저장만 함 |
| 잔액이 고정값 | 거래를 넣거나 결제를 완료해도 계좌 잔액이 변하지 않음 |
| 대시보드에 기간 개념 없음 | 2030년 이벤트도 이번 달 사용 가능 자금에서 차감 |
| 계좌 합계 불일치 | `/accounts` 는 240만, `/dashboard` 는 120만 |
| 거래 입력 불가 | `POST /transactions` 없음. 시드로만 거래가 생김 |
| 카드·예산 미연동 | 카드 결제일, 예산 한도가 저장만 되고 계산에 쓰이지 않음 |
| AI 가 질문을 읽지 않음 | 무엇을 물어도 같은 템플릿 답. 반복 지출 "탐지"는 등록된 규칙을 그대로 돌려줌. 근거 조회는 당시가 아닌 현재 값을 재계산 |
| OpenAI 요청 형식 버그 | `role:"tool"` 메시지를 `tool_call_id` 없이 보냄 → 실제 API 는 400 으로 거부 |
| 인증 없음 | `X-User-Id: 3` 헤더만 붙이면 3번 사용자로 행세. 식별 실패 시 1번 사용자로 동작 |
| 500 에러에 내부 메시지 노출 | 예외 메시지를 그대로 응답에 실음 |

## 1차 — 핵심 금융 로직

| 작업 | 내용 |
| --- | --- |
| 반복 규칙 | 조회하는 달마다 예정 이벤트를 자동 생성(lazy). 매달·매주·매년, 종료일 반영 |
| 규칙 수정·비활성화 | 아직 지나지 않은 예정분만 다시 맞추고, 지난 기록은 보존 |
| 카드 청구 | 전월 카드 사용액을 합쳐 당월 결제일에 청구 이벤트 자동 생성 |
| 거래 CRUD | `POST/PATCH/DELETE /transactions` 추가, 거래에 카드 연결 |
| 대시보드 | 조회 기간 안의 이벤트만 계산 |
| 계좌 합계 | `totalBalance` 를 자산 포함 계좌만으로 계산해 대시보드와 일치 |
| 예산 | `GET /budgets/monthly/status` 로 한도 대비 지출·초과 여부, 월 지정 조회 |
| DB | V3: `transactions.card_id`, `financial_events.recurring_rule_id/card_id` + 중복 방지 UNIQUE |

작업 중 발견해 고친 버그: 시드 초기화 시 외래 키 순서가 틀려 500 이 나던 문제, 규칙 금액을 바꾸면 지난 이벤트까지 바뀌던 문제.

## 2차 — 전체 기능 완성

| 작업 | 내용 |
| --- | --- |
| 잔액 원장 | 계좌 거래(지출·수입·이체)가 잔액에 즉시 반영, 수정·삭제 시 되돌림. 이벤트를 `PAID` 로 바꾸면 결제 계좌에서 차감 |
| 잔액 수동 수정 | `PATCH /accounts/{id}` 의 `balance` 로 실제 통장과 맞추기 |
| 자산 CRUD | 계좌·카드·카테고리 등록·수정·삭제 (삭제 정책은 [04](04-의사결정-기록.md)) |
| 시뮬레이션 | 지출일에 따라 최저 잔액과 그 날짜가 달라지도록 |
| 알림 | 5종: 잔액 마이너스, 잔액 낮음, 7일 안 결제, 예산 초과, 예산 임박 |
| AI | 도구 8개 + Tool Calling. 키가 없으면 규칙 기반 답변기가 같은 도구로 답함. 대화 이력 전달, 근거(도구 결과) 저장 |
| 반복 지출 탐지 | 최근 6개월 거래에서 3개월 이상·금액 변동 20% 이하인 상호를 찾아 등록용 규칙까지 제안 |
| 인증 | 이메일·비밀번호 가입·로그인, BCrypt, JWT, Spring Security |
| 예외 처리 | 400/409 를 올바르게 구분, 500 은 일반 메시지만 |
| DB | V4: 인증 컬럼, 잔액 원장 컬럼, AI 근거 컬럼 |

## 4차 — AI 자동 선택, 리팩토링

| 작업 | 내용 |
| --- | --- |
| AI 제공자 자동 선택 | `AI_PROVIDER` 기본값 `auto`: 키가 있으면 외부 AI, 없으면 규칙 기반. 이전에는 키를 넣어도 `rule-based` 기본값 때문에 무시됨 |
| 테스트 보호 | 테스트는 규칙 기반으로 고정 (개발 PC 에 키가 있어도 유료 API 를 부르지 않도록) |

| 리팩토링 | `MoneyWeatherService`(824줄, 공개 메서드 27개)를 역할별 서비스 6개로 분리. 컨트롤러도 도메인별로 분리. **URL·요청·응답·트랜잭션 경계는 그대로**, 테스트 파일 수정 없이 117개 통과 |

## 기존 대비 달라진 점

### ⚠️ 호환성이 깨지는 변경

예전 API 에 맞춰 짠 코드(프론트, 테스트 스크립트 등)가 있다면 아래를 확인하세요.

| 변경 | 예전 | 지금 |
| --- | --- | --- |
| 사용자 식별 | `X-User-Id` 헤더, `?userId=` 쿼리, 식별 실패 시 1번 사용자 | **`Authorization: Bearer <JWT>`만.** 없으면 401 |
| 토큰 발급 | `POST /auth/dev-token {userId}` (비밀번호 없음) | **삭제.** `POST /auth/login {email, password}` |
| `userId` 파라미터 | `/users/me`, `/accounts`, `/cards`, `/categories` 에 `?userId=` | 삭제 (보내도 무시) |
| `GET /accounts` 의 `totalBalance` | 조회된 계좌 전부 합계 | **자산 포함 계좌만**. 전체 합계는 `allAccountsBalance` |
| `GET /transactions` 정렬 | 정해지지 않음 | 최신순(날짜 내림차순). `totalPages` 추가, `size` 최대 100 |
| `POST /available-funds/simulations` | `before/after` 에 가용 자금·날씨만 | `minimumBalance`, `minimumBalanceDate`, `forecastWeather`, `title`, `spendingDate`, `targetDate` 추가. 지출일이 결과에 반영됨 |
| `GET /forecast-alerts` | `alerts` 에 위험 요약 1개 | `{from, to, count, alerts:[{type, severity, date, title, message, amount}]}`, `from`/`to` 파라미터 |
| `POST /agent/detect-recurring` | 등록된 규칙 목록, `confidence: 0.95` 고정 | 실제 탐지 결과. `merchant, monthsObserved, typicalAmount, confidence, reason, suggestedRule` |
| `POST /agent/recommend-actions` | `actions: ["문장", ...]` | `actions: [{type, priority, message, detail}]`, `availableAmount` 추가 |
| `GET /agent/evidence/{id}` | `{sources, snapshot}` (현재 값 재계산) | `{content, provider, sources, toolCalls:[{name, arguments, result, ...}]}` (저장된 당시 값) |
| `POST /agent/chat` | `sources` 고정 3개 | 실제로 호출한 도구 목록. `provider`, `toolCalls` 추가 |
| `POST /agent/analyze-spending` | 기준 월만 | `?month=` 지원, `ranking` 추가 |
| 카드 청구 이벤트 제목 | `카드 결제` (수동 시드) | `<카드명> 결제` (예: `Deep Dream 결제`, 자동 생성) |
| 시드 | 거래 3건, 이벤트 4건 수동 | 거래 15건(6~9월), 수동 이벤트 2건 + 자동 생성 2건, 데모 로그인 계정 |
| H2 콘솔 | 기본 켜짐 | 기본 꺼짐 (`H2_CONSOLE_ENABLED=true`) |
| 오류 응답 | 파싱 오류·파라미터 오류가 500, 500 에 내부 메시지 노출 | 400 으로 구분, 500 은 일반 메시지 |
