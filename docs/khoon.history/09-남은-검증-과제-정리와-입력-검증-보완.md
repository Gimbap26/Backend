# 09. 남은 검증 과제 정리와 입력 검증 보완

## 1. 문서 목적

이 문서는 07번 문서에 남아 있던 알려진 문제 중 실제 코드로 해결한 항목과, 이번 점검에서 다시 확인한 검증 상태를 정리한다.

이번 작업의 기준은 다음과 같다.

- 잘못된 데이터가 저장될 수 있는 입력 검증 문제는 코드로 해결한다.
- 실제 프로젝트 코드와 어긋난 문서는 현재 구현 기준으로 바로잡는다.
- 로컬에서 실행 가능한 자동 테스트는 다시 실행해 확인한다.
- 실제 PostgreSQL 기동과 Docker 이미지 빌드는 Docker 데몬이 실행되어야 하므로 별도 환경 검증 항목으로 남긴다.

## 4. 상세 처리 내용

### 4.1 PATCH 입력 검증

기존에는 등록 API에는 검증이 있었지만, 일부 수정 API는 검증 없이 service로 요청이 전달될 수 있었다.

보완 후 다음 요청은 400으로 거부된다.

```json
{
  "amount": -1
}
```

```json
{
  "title": ""
}
```

```json
{
  "merchant": ""
}
```

대상 API는 다음과 같다.

| API | 보완 내용 |
|---|---|
| `PATCH /api/v1/transactions/{transactionId}` | `amount` 양수, `merchant` 빈 문자열 거부 |
| `PATCH /api/v1/financial-events/{eventId}` | `amount` 양수, `title` 빈 문자열 거부 |
| `PATCH /api/v1/recurring-rules/{id}` | `amount` 양수, `title` 빈 문자열 거부, `dayOfMonth` 1~31 |

### 4.2 월 반복 규칙 검증

`MONTHLY` 반복 규칙은 매월 며칠에 발생하는지 알아야 하므로 `dayOfMonth`가 필수다.

보완 후 다음 요청은 400으로 거부된다.

```json
{
  "title": "날짜 없는 월반복",
  "recurrenceType": "MONTHLY",
  "startDate": "2026-10-01",
  "amount": 50000,
  "eventType": "SUBSCRIPTION",
  "direction": "OUTFLOW"
}
```

또한 기존 `WEEKLY` 규칙을 `MONTHLY`로 바꾸면서 `dayOfMonth`를 주지 않는 경우도 거부된다.

## 7. 남은 확인 항목

코드 누락으로 남은 MVP 기능은 없다.

남은 항목은 실제 외부 실행 환경이 필요한 검증이다.

| 항목 | 필요한 조건 | 확인 방법 |
|---|---|---|
| 실제 PostgreSQL 기동 | Docker Desktop 또는 PostgreSQL 서버 실행 | `docker compose -f docker-compose.prod.yml up -d --build` 후 health 확인 |
| Docker 이미지 빌드 | Docker 데몬 실행 | `docker compose -f docker-compose.prod.yml up -d --build` |
| 실제 OpenAI 답변 품질 | 유효한 `AI_API_KEY`와 크레딧 | `POST /api/v1/agent/chat` 응답의 `provider`가 `openai-compatible`인지 확인 |

## 8. 최종 정리

이번 작업으로 07번 문서의 K1, K2는 해결되었다.

자동 테스트는 121개 모두 통과했으며, 입력 검증 보완에 대한 회귀 테스트도 추가되었다. AI Agent 문서도 실제 코드 구조에 맞게 수정했다.

현재 남은 것은 코드 구현 문제가 아니라 Docker 데몬, 실제 PostgreSQL 서버, 외부 OpenAI 크레딧처럼 실행 환경이 필요한 검증 항목이다.
